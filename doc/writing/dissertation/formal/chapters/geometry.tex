\section{Geometry}
A fundamental step in developing a FEM or FVM code
is the indexing of geometric entities.
The mesh index data structure implemented in the code is inspired by the classical 
viewpoint of Boundary Representation (BREP), 
originally introduced by~\cite{10.1145/1499949.1500071}.
In the two-dimensional case,
each element is bounded by a set of edges,
and each edge is defined by a set of vertices.
We begin by introducing the following notations for global geometric objects:
\begin{equation}\label{eq:globalgeometricOBJ}
		  \begin{aligned}
					 \text{Vertex} \quad &V_i, \quad i\in ID_V,\\
					 \text{Edge} \quad &E_i, \quad i\in ID_E,\\
					 \text{Element (i.e. Face)}  \quad &F_i, \quad i\in ID_F,
		  \end{aligned}
\end{equation}
where $ID_V$, $ID_E$ and $ID_F$ denote countable 
sets containing all unique global indices for vertices, edges, and elements 
(or cells, i.e., the faces),
respectively. Superscripts are used to indicate subsets of these global index sets. 
For example, 
$ID^{E_i}_{V} \subset ID_{V}$ represents the set of global  
vertex indices associated with edge $E_i$, which is a subset of the global vertex index set.

We again present the following notations
for local geometric entities:
\begin{equation}\label{eq:localgeometricOBJ}
		  \begin{aligned}
					 \text{Vertex} \quad &v_i, \quad i\in id_v,\\
					 \text{Edge} \quad &e_i, \quad i\in id_e,\\
					 \text{Element (i.e. Face)} \quad &f_i, \quad i\in id_f,
		  \end{aligned}
\end{equation}
where $id_v$, $id_e$ and $id_c$ denote countable sets
containing local index for vertices, edges and elements
corresponding to a given geometrical object.
Superscripts are used to indicate the target geometrical object. 
For example,
$id_v^{E_i} = \{0,1\}$ represents the local index of the two vertices 
bounding the edge $E_i$.

We establish a one-to-one mapping between local and global indices through
a local-to-global map, defined as 
\begin{equation}
		  f: id \rightarrow ID.
\end{equation}
In practice, it is often unnecessary to explicitly define a local-to-global
mapping.
On the other hand, for each local array containing global indices, the array indices
naturally represent the local index set.
%Consider an array(vector) containing
%global index, the array index is a natural representation for 
%local index set.
%With the help of array representation, we
%can reverse to a global to local mapping within each target geometrical
%objects.
This array-based representation enables the implicit construction of a global-to-local
mapping within each geometric entity.

\subsection{General Unstructured Mesh}
In both FEM and FVM solvers, an element object $F_i$ (mesh cell or ``faces") 
serves as the fundamental geometry entity.
These elements will be assumed to be strictly convex polygons,
tessellating space, and sharing complete edges.
We start with a brief analysis of the information each face
should access from its local perspective.
Each element $F_i$ should have the access to the following geometric
objects:
\begin{itemize}
		  \item The adjacent elements connected by edges;
		  \item The adjacent elements connected with vertices, 
					 but not sharing an edge;
		  \item The vertices of the polygonal element;
		  \item The edges that bound this element.
\end{itemize}
%Within the local set, we can relate edges and vertices directly.
%For convenience, 
%each edge $j$ should has links to:
At the same time, each edge $E_j$ should have access to:
\begin{itemize}
		  \item Two adjacent elements that share this edge;
		  \item Two vertices that bound this edge.
\end{itemize}

For simplicity, we restrict our discussion to quadrilaterals in
the following discussions.
In FEM and FVM computations, we assume an orientable mesh, where 
``clockwise" and ``counterclockwise" orientations can be consistently defined.
This allows the use of a half-edge data structure to systematically manage edge directions.
\begin{figure}[ht]
\centering
\input chapters/tikz/halfedge.tex
		  \caption{An illustration of the half-edge data structure for a quadrilateral.}
		  \label{fig:halfedge}
\end{figure}

Figure~\ref{fig:halfedge} illustrates a simple half-edge 
data structure applied to a quadrilateral mesh. 
For each element $F_i$,
the associated vertex $V_i$ references the outgoing link $l_i$ that points to the next vertex $V_{i^+}$,
while the incoming link $l_{i^-}$, which points to $V_i$  is not directly referenced.
Consequently, a normal ``direction" can be determined from the perspective of each element object $F_i$ in 
accordance to the direction of links.

\section{Logically Rectangular Mesh}
Mesh generation is not the primary focus of this project; therefore,
we restrict to a logically rectangular mesh and adopt a simple approach to
generating a quadrilateral mesh.
The quadrilateral mesh is generated by randomly distorting each 
interior vertex coordinates of a uniform rectangular mesh.
However, the indexing of geometrical entities remain unchanged despite
the vertex perturbation.

In our implementation, all indices are represented using Cartesian coordinates.
This allows the local-to-global mapping of geometric entities to be established easily through linear functions.
All geometric entities can be indexed using Cartesian coordinates straightforwardly.
For a mesh with $M\times N$ cells, the total number of vertices
is $(M+1)\times (N+1)$, while the total number of edges is 
$M\times (N+1) + (M+1)\times N $. 
Horizontal edges are indexed first, and vertical edges are indexed
sequentially starting from the offset $M\times (N+1)$.

Before we delve into the indexing conventions of this type of mesh,
we introduce a reshape function that facilitates communication between $N$-dimensional data
and its one-dimensional representation.

\subsection{Reshape of $N$-dimensional Data}
The natural representation of a 2D Cartesian index is a pair $(i,j)$. 
In practice,
it is often reshaped into a 1D array for more efficient
computational handling. We introduce a general reshape function
that projects $N$-dimensional data to a one-dimensional data. 
This reshape function can also be used for tensor data, e.g., the Jiang-Shu smoothness
indicators~\eqref{eq:JSsmoothnessIC}.

Consider a bijective map between $N$-dimensional data and its one-dimensional data representation as
\begin{equation}
		  i \leftrightarrow (i_0, i_1 , \ldots, i_{N-1}).
\end{equation}
Algorithm~\ref{alg:reshape} illustrates a
simple implementation of the reshape function.
The inverse operation, reshaping one-dimensional data back into $N$-dimensional form, 
can be achieved using modulo and integer division operations.
\begin{algorithm}[htb]
\caption{Reshape $N$-dimensional data\label{alg:reshape}}
		  Consider a $N$-dimensional array of size $\{n_0\times n_i\times \ldots n_{N-1}\}$.
		  \vspace{0.3cm}

Let $I=0$ be the variable storing the output, and $a=1$ be the intermediate multiplier.
		  \vspace{0.3cm}

		  Consider an input $N$-dimensional index $\{i_0, i_1, \ldots, i_{N-1}\}$.
		  \vspace{0.3cm}

\begin{algorithmic} [1]
		  \For{\rm rank $r= 0,1,\ldots, N-1$} 
		  \vspace{0.3cm}
		  \State $I = I + i_r \times a$.
		  \vspace{0.3cm}
		  \State $a = a\times n_r$.
		  \vspace{0.3cm}
		  \EndFor
\end{algorithmic}
\end{algorithm}

Throughout this work, we use these two index representations interchangeably.
To emphasize the relation between $N$-dimensional
and its one-dimensional representation in Algorithm~\ref{alg:reshape}, we introduce the following notation as
\begin{equation}\label{eq:reshapenotation}
		  i(i_0, i_1, \ldots, i_{N_1})_{n_0, n_1, \ldots, n_{N-1}},
\end{equation}
where $i$ denotes the mapping from the $N$-dimensional data to the one-dimensional data, while $(i_0, i_1, \ldots, i_{N-1})$ 
is the corresponding $N$-dimensional index. The $N$-dimensional quantities $n_0, n_1, \ldots, n_{N-1}$ represent
the respective sizes along each dimension of the $N$-dimensional array. 

\subsection{Local Vertex Representation}
We now represent the local vertex index with the new notation~\eqref{eq:reshapenotation}.
For any vertex, we can represent its local index as
\begin{equation}
		  a(a_0,a_1)_{2,2},
\end{equation}
where $a_0, a_1 \in \{0,1\}$. We can link to the next point $b$ simply by
adding $1$ to the one-dimensional index under the understanding of modulo as
\begin{equation}
		  b \equiv a+1 \Mod{4},
\end{equation}
which is a simple half-edge data representation.
The direction is naturally defined by this addition operation.

\subsection{Local to Global Index Convention}
Recall that local vertices and edges are indexed starting from the bottom left corner, 
as illustrated in Figure~\ref{fig:meshexample}.
We now define the local to global index mapping with the help of the new notation~\eqref{eq:reshapenotation}.
Consider any local vertex $v_i$ associated to a quadrilateral element $F_{I(I_0,I_1)_{M,N}}$ with the local index
\begin{equation}
id_v \ni i(i_0, i_1)_{2,2} = i_0 + 2i_1.
\end{equation}
We find the corresponding global index with ease as

We continue our discussion the local-to-global mapping for vertical and horizontal edges.
Consider edge $e_i$ defined by the vertex $id_v \ni i(i_0,i_1)$ and its half-edge link $l_i$:
\begin{itemize}
		  \item Global index of the horizontal edge is
\begin{equation}
		  ID_E \ni I(I_0,I_1+i_1)_{M,N+1};
\end{equation}
		  \item Global index of the vertical edge is
\begin{equation}
		  ID_E \ni I(I_0+i_0,I_1)_{M+1,N} + M\times (N+1).
\end{equation}
\end{itemize}

\section{Dofs and MFEM assembly}
In FEM and FVM computations, it is necessary to associate geometrical entities with
degrees of freedom (dofs). For FVM schemes, the dofs associated with
edge fluxes are straightforward. However, in MFEM, the treatment of dofs requires
more careful handling, particularly for those located on the boundary. 
Following the approach of~\cite{FEMHughes}, we employ three data processing arrays: ID, IEN and LM
arrays.
We begin by the introduction of these three arrays as:
\begin{itemize}
		  \item IEN array,
					 \begin{equation}
								\text{IEN}(a,e) = A,
					 \end{equation}
					 where $a$ is the local dof index, $e$ is the global element
					 number and $A$ is the global dof index;
		  \item ID array,
					 \begin{equation}
								\text{ID}(A) = \left \{ 
								\begin{aligned}
										  &P, \quad A \not\in \text{Essen}, \\
										  &0, \quad A \in \text{Essen},
								\end{aligned}
								\right.
					 \end{equation}
					 where $P$ is the position used in global matrix assembly, 
					 and $\text{Essen}$ denotes the boundary assigned with 
					 essential boundary condition;
		  \item LM array,
					 \begin{equation}
								\text{LM} = \text{ID}(\text{IEN}(a,e)).
					 \end{equation}
\end{itemize}
In actual code implementation, we create the LM array by screening all dofs prior 
to computation, while the IEN and ID arrays are not stored explicitly.
